# Hololive Dreams Auto Collect Cooking — 1.0.1

[English](README.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Indonesian](README.id.md) · [简体中文](README.zh-CN.md)

Windows版『hololive Dreams』の「そろえてクッキング」を自動操作するプログラムです。ゲーム画面から食材を認識し、通常のマウス入力で選択します。リザルト画面の後は次のプレイに進みます。

## ダウンロード

[GitHub Releases](https://github.com/harrykuang-dev/Hololive-Dreams-Collect-Cooking-Auto/releases/tag/v1.0.1)から `Collect-Cooking-Auto-v1.0.1-win64.7z.*` の全分割ファイルを同じフォルダーにダウンロードしてください。7-Zipで `.7z.001` を展開し、フォルダー内の `Collect-Cooking-Auto-v1.0.1.exe` を実行します。

EXEの隣にある `_internal` フォルダーも必要です。Python、推論ライブラリ、5個の学習済みモデルを同梱しています。ダウンロードの確認には `SHA256SUMS.txt` を使用できます。`models.zip` はソースから実行する場合のモデルです。GitHubのソースZIPでは依存パッケージとモデルを別途導入してください。

## 機能

- レシピ、残りの必要数、トレイを認識し、食材の取得、3個消し、皿のシャッフルを計画します。
- 「**標準**」（ResNet18）と「**高性能**」（ResNet101）を選択できます。標準は処理負荷が低く、高性能は余裕のあるパソコンに適しています。
- モデルの読み込みとプレイ開始を分離し、読み込んだ位置分類モデルを補助候補の検証にも共用します。
- 目標プレイ回数を指定し、1回の終了後に自動で続行して、目標回数で停止します。
- 英語、繁体字中国語、日本語、韓国語、インドネシア語、簡体字中国語に対応します。言語設定はプログラムの画面に適用されます。
- ショートカットの変更、実行ログ、任意のローカル診断に対応します。

## 使い方

1. ゲームを開き、「そろえてクッキング」に入ります。
2. EXEを実行し、言語、認識モデル、1以上の目標回数を設定します。初期値は5回です。
3. 「**モデルを読み込む**」をクリックし、準備完了を待ちます。
4. 「**開始**」をクリックすると、プログラムがゲームの最小化を解除し、前面への切り替えを試みます。ゲーム内で **F8** を押して開始することもできます。Windowsに切り替えを制限された場合は手動でゲームに戻り、他のウィンドウで隠さないでください。
5. **F8** で一時停止／再開、**Esc** または「**停止**」で終了します。別のウィンドウに移ると入力を一時停止します。ゲームに戻ってF8で再開できます。モデルを変更する場合は停止してから選び直し、再読み込みしてください。

ショートカット欄をクリックし、キーまたはCtrl／Alt／Shiftとの組み合わせを押すと変更できます。入力を完了せずに欄を離れた場合は以前の設定を保持します。設定は次回起動時にも使用されます。

## 動作条件と制限

Windows 10／11 x64とWindows版ゲームに対応します。ゲームの表示領域は16:9にし、ディスプレイをオンにして画面を表示したまま使用してください。利用可能なNVIDIA CUDAを自動選択し、それ以外ではCPUで推論します。リソースに余裕がない場合は標準モデルを選んでください。

展開後のフォルダーは約5.3 GBです。ダウンロードと展開用の空き容量も必要です。完了回数は実行の進捗を表します。料理数とスコアはゲームのリザルト画面で確認してください。食材の移動、遮蔽、パソコンの性能、ゲーム更新が認識に影響します。

## 技術的な仕組み

### 画面取得と画像処理

[画面取得モジュール](outputs/kitchen-bot/async_recording.py)は独立したスレッドでWindows GDIを使用し、毎秒20フレームの取得を要求します。動画のエンコードを待たずに新しい画像を認識へ渡します。[認識処理](outputs/kitchen-bot/perception.py)は画像を1536×864に正規化し、盤面の448×280画像を分割します。クリック位置は実際の拡大率と上下のオフセットで変換します。

### 食材認識とモデルの共用

主分割モデルが可視の食材領域を抽出し、選択した位置分類モデルがクリック周囲の64×64画像を96×96に拡大して判定します。共用のアイコン分類モデルがレシピとトレイを読み、数字テンプレートと固定UI画像が必要数と画面状態を識別します。

主経路が待機またはシャッフルを選ぶ場合、[補助位置検出](outputs/kitchen-bot/supplemental_food.py)でタマネギ、エビフライ、ツナ缶の候補を必要に応じて探し、読み込み済みの位置分類モデルで検証します。位置分類モデルは選択した標準または高性能の一方だけを読み込みます。[モデルの詳細](docs/model-options.md)を参照してください。

### 選択計画とシャッフル間隔

[計画処理](outputs/kitchen-bot/planner.py)はレシピ、トレイの推定、確認待ちの選択、最近失敗した位置を保持します。必要な食材と3個消しを優先し、必要数の変化とトレイの表示から結果を確認します。シャッフルには実際のボタン入力から5秒以上の間隔と、新しい画面でのボタン利用可能状態が必要です。

### 移動の検証と続行

[オプティカルフロー](outputs/kitchen-bot/motion.py)で入力前の移動を推定し、[最新画像の検証](outputs/kitchen-bot/latest_click.py)で注文、画面状態、観測位置と予測位置の食材を確認します。追跡に失敗した必要食材は、制限付きの局所再検出で再試行できます。[セッション制御](outputs/kitchen-bot/session_flow.py)は右下の続行ボタンを認識し、リザルトやメニューから次へ進みます。

## 不具合報告と開発者モード

認識、クリック、続行の問題は [GitHub Issues](https://github.com/harrykuang-dev/Hololive-Dreams-Collect-Cooking-Auto/issues)に報告してください。「**開発者モード**」を有効にしてから再現すると、認識結果、入力のタイミング、ゲーム画像、処理時間の概要をローカルに保存します。有効にすると処理負荷が増えます。自動アップロードは行いません。

隣の `?` から診断フォルダーを確認して開けます。

```text
%LOCALAPPDATA%\CollectCookingAuto\sessions\
```

実行終了時に日時付きのZIPを作成します。バージョン、選択したモデル、ゲーム言語、解像度、Windowsの表示倍率、問題の説明、診断ZIPを添付してください。
