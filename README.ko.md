# Hololive Dreams Auto Collect Cooking — 1.1.0

[English](README.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Indonesian](README.id.md) · [简体中文](README.zh-CN.md)

Windows판 *hololive Dreams*의 모아 쿠킹을 자동으로 플레이하는 요리 프로그램입니다. 게임 화면에서 식재료를 인식하고 일반 마우스 입력으로 선택하며, 결과 화면 이후 다음 판을 진행합니다.

## 다운로드

[GitHub Releases](https://github.com/harrykuang-dev/Hololive-Dreams-Collect-Cooking-Auto/releases/tag/v1.1.0)에서 `Collect-Cooking-Auto-v1.1.0-win64.7z`를 다운로드하세요. 7-Zip으로 압축을 해제한 뒤 폴더의 `Collect-Cooking-Auto-v1.1.0.exe`를 실행하세요.

EXE 옆의 `_internal` 폴더를 유지하세요. Python, 추론 라이브러리와 모델 가중치 5개가 포함되어 있습니다. `SHA256SUMS.txt`로 다운로드를 확인할 수 있으며 `models.zip`은 소스 실행용입니다. GitHub의 소스 ZIP은 의존 패키지와 모델을 별도로 설치해야 합니다.

## 기능

- 레시피, 남은 필요 수량과 슬롯을 인식하여 식재료 선택, 3개 제거와 접시 섞기를 계획합니다.
- **표준**(ResNet18)과 **고급**(ResNet101)을 제공합니다. 표준은 연산 요구량이 낮고 고급은 성능에 여유가 있는 컴퓨터에 적합합니다.
- 모델 불러오기와 게임 시작을 분리하며, 불러온 위치 분류 모델로 보조 후보도 검증합니다.
- 목표 판수를 설정하고 한 판이 끝나면 자동으로 이어서 진행하며 목표에 도달하면 중지합니다.
- 영어, 번체 중국어, 일본어, 한국어, 인도네시아어와 간체 중국어를 지원합니다. 언어 선택은 프로그램 화면에 적용됩니다.
- 사용자 지정 단축키, 실행 기록과 선택 가능한 로컬 진단을 제공합니다.

## 사용 방법

1. 게임을 열고 모아 쿠킹에 들어가세요.
2. EXE를 실행하고 언어와 인식 모델을 선택한 뒤 양의 정수로 목표 판수를 입력하세요. 처음에는 5판으로 설정됩니다.
3. **모델 불러오기**를 누르고 준비 완료를 기다리세요.
4. **시작**을 누르면 프로그램이 최소화된 게임 창을 복원하고 앞으로 가져오기를 시도합니다. 게임에서 **F8**을 눌러 시작할 수도 있습니다. Windows가 전환을 차단하면 직접 게임으로 돌아가고 창을 가리지 마세요.
5. **F8**은 일시 정지/재개, **Esc** 또는 **중지**는 실행 종료입니다. 다른 창으로 이동하면 입력이 일시 정지됩니다. 게임으로 돌아가 F8로 재개하세요. 모델을 바꾸려면 먼저 중지한 뒤 다시 선택하여 불러오세요.

단축키 입력란을 누르고 원하는 키나 Ctrl/Alt/Shift 조합을 누르면 변경됩니다. 입력을 끝내지 않고 벗어나면 이전 설정을 유지합니다. 설정은 다음 실행에도 저장됩니다.

## 실행 조건과 제한

Windows 10/11 x64와 Windows판 게임이 필요합니다. 게임 표시 영역을 16:9로 유지하고 모니터를 켠 상태에서 게임을 표시하세요. 단일 완전판에 모든 추론 라이브러리와 공용 FP32 ONNX 모델 한 세트를 포함합니다. 호환 NVIDIA GPU는 TensorRT를, 다른 지원 DirectX 12 GPU는 DirectML을 자동 사용하며 마지막으로 CPU로 전환합니다. CPU나 성능이 낮은 GPU는 클릭 시간 조건을 충족하지 못할 수 있습니다.

압축 해제한 폴더는 약 2.9 GB이며 다운로드와 압축 해제를 위한 여유 공간도 필요합니다. 완료 판수는 실행 진행 상황입니다. 요리 수와 점수는 게임 결과 화면에서 확인하세요. 식재료 이동, 가림, 컴퓨터 성능과 게임 업데이트가 인식에 영향을 줄 수 있습니다.

## 기술 구현

### 화면 캡처와 이미지 처리

[캡처 모듈](outputs/kitchen-bot/async_recording.py)은 독립 스레드에서 Windows GDI로 게임 표시 영역을 캡처하며 초당 20프레임을 요청합니다. 영상 인코딩을 기다리지 않고 최근 이미지를 인식에 전달합니다. [인식 과정](outputs/kitchen-bot/perception.py)은 화면을 1536×864로 정규화하고 448×280의 보드 이미지를 분할합니다. 클릭 위치는 실제 배율과 상단 오프셋으로 변환합니다.

### 식재료 인식과 모델 공유

주 분할 모델이 보이는 식재료 영역을 찾고, 선택한 위치 분류 모델이 클릭 주변의 64×64 이미지를 96×96으로 변환하여 판정합니다. 공용 아이콘 분류 모델은 레시피와 슬롯을 읽으며 숫자 템플릿과 고정 UI 이미지로 필요 수량과 화면 상태를 구분합니다.

주 경로가 대기하거나 접시를 섞으려 할 때 [보조 위치 검출](outputs/kitchen-bot/supplemental_food.py)이 양파, 새우튀김과 참치캔 후보를 필요에 따라 찾습니다. 이미 불러온 위치 분류 모델이 후보를 검증합니다. 선택한 표준 또는 고급 위치 분류 모델 하나만 불러옵니다. [모델 설명](docs/model-options.md)을 참고하세요.

### 선택 계획과 접시 섞기 간격

[계획 모듈](outputs/kitchen-bot/planner.py)은 레시피, 슬롯 추정, 확인 중인 선택과 최근 실패 위치를 유지합니다. 필요한 식재료와 3개 제거를 우선하며 필요 수량 변화와 슬롯 표시로 결과를 확인합니다. 접시 섞기는 실제 버튼 입력 사이에 최소 5초가 필요하고 최근 화면에서 버튼이 사용 가능한 상태여야 합니다.

### 이동 검증과 다음 판 진행

[광학 흐름](outputs/kitchen-bot/motion.py)으로 입력 직전의 이동을 추정하고 [새 화면 검증](outputs/kitchen-bot/latest_click.py)으로 주문, 화면 상태, 관측 위치와 예측 위치의 식재료를 확인합니다. 추적에 실패한 필요 식재료는 제한된 지역 재검출로 다시 시도할 수 있습니다. [세션 제어](outputs/kitchen-bot/session_flow.py)는 오른쪽 아래 진행 버튼을 인식하여 결과 화면과 메뉴에서 다음 판으로 이동합니다.

## 문제 보고와 개발자 모드

인식, 클릭이나 다음 판 진행에 문제가 있으면 [GitHub Issues](https://github.com/harrykuang-dev/Hololive-Dreams-Collect-Cooking-Auto/issues)에 보고하세요. **개발자 모드**를 켠 뒤 재현하면 인식 결과, 클릭 시점, 게임 화면과 성능 요약을 로컬에 저장합니다. 활성화하면 처리 부하가 늘어나며 자료는 자동으로 업로드되지 않습니다.

옆의 `?`에서 진단 폴더를 확인하고 열 수 있습니다.

```text
%LOCALAPPDATA%\CollectCookingAuto\sessions\
```

실행이 끝나면 날짜와 시간이 포함된 ZIP을 만듭니다. 프로그램 버전, 선택 모델, 게임 언어, 해상도, Windows 배율, 문제 설명과 진단 ZIP을 함께 제공하세요.

개발자 모드는 각 판의 확인된 점수, 요리 수, 클릭, 판단, 대기 이유와 처리 시간을 JSONL로 계속 보존합니다. 결과 화면과 일반 이미지는 같은 용량 제한에 따라 오래된 순서로 삭제하며, 남아 있는 이미지는 `image-index.json`에 기록합니다. 확인하지 못한 숫자는 null로 표시하고 이유를 남깁니다. 진단 ZIP은 파일당 최대 20 MB이며 텍스트만으로 초과하면 여러 ZIP으로 분할합니다. 전체 원본 텍스트 파일은 로컬에 보존합니다.
